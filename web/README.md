# O3GO Campaigner · Web

Отдельный фронтенд на **Next.js App Router, React, TypeScript, Tailwind CSS 4, shadcn/ui (Radix), TanStack Table 8 и TanStack Query**. Данные и интерфейс приложения рендерятся на клиенте; `ClientRoot` отключает SSR рабочего пространства. Next.js обслуживает приложение и проксирует API. Бэкенд, старый `html` и существующий `frontend` не изменены.

## Запуск

Требуется Node.js ≥22.12 и работающий FastAPI с PostgreSQL/Redis.

```bash
cd web
npm ci
cp .env.example .env.local
npm run dev
```

Открыть [localhost:3000](http://localhost:3000). Адрес API задаётся через `API_ORIGIN` (по умолчанию `http://127.0.0.1:5001`). Запросы `/api/v1/*` проксируются прозрачным Route Handler Next.js с сохранением завершающего слеша, поэтому не требуется менять CORS или серверный код. При изменении `API_ORIGIN` перезапустите сервер. Эта настройка читается во время выполнения и не попадает в браузерный JavaScript.

С телефона в той же сети открывайте `http://<локальный IPv4 компьютера>:3000`. Dev-сервер слушает все интерфейсы, а `allowedDevOrigins` в `next.config.ts` автоматически разрешает текущие локальные IPv4-адреса для загрузки интерфейса и HMR. После смены сети/IP перезапустите `npm run dev`. Сессии браузера отдельные для localhost и IP, поэтому на телефоне потребуется войти заново.

Если API доступен браузеру напрямую, можно задать `NEXT_PUBLIC_API_ORIGIN`; тогда API должен разрешать CORS для адреса фронтенда и cookie credentials. Для обычного запуска оставьте эту переменную пустой. Логин: существующая учётная запись Campaigner.

```bash
npm run typecheck
npm test
npm run build
npm run test:proxy
npm start
```

Production работает на порту 3000. Из корня репозитория: `docker compose up --build -d next-web`. Сервис `next-web` использует внутренний API `http://api:8000`; для другого бэкенда задайте `WEB_API_ORIGIN` в корневом `.env`. Адрес читается во время выполнения, пересобирать образ при смене API не нужно. Образ использует Next.js standalone и запускается от пользователя `node`.

Отдельный запуск фронтенда: `docker compose -f compose.yml up --build -d` из папки `web`; в этом случае API задаётся переменной `API_ORIGIN` и по умолчанию доступен на хосте через порт 5001.

## Интерфейс

- Кампании: фильтры, сортировка, пагинация, мультивыбор; запуск, пауза, остановка, повтор недоставленных, проверка номеров, Excel, очистка и удаление с подтверждением. Статистика кампании и подробная таблица сообщений.
- Мастер кампании: CSV/TXT/XLS/XLSX или вставка текста, реальные образцы колонок после загрузки файла, сопоставление телефона и пяти полей, персонализация, сокращение ссылок, AI, Clicker, приоритеты, таймауты, даты и недельное расписание UTC. В формах используется исходный jQuery Weekly Scheduler из `html`: сетка 7×24 с выбором дней, часов, полусуток и диапазонов. Файлы библиотеки сохранены в `public/vendor` без изменений; React-адаптер добавляет клавиатуру и постоянное выделение диапазона касанием внутри ячеек. Для нативной прокрутки пальцем используются заголовки часов и колонка дней. Создание не запускает рассылку.
- Сайдбар по умолчанию свёрнут до иконок; основные разделы — кампании, теги, API-ключи, пользователи и руководство. Внизу — круглая акцентная иконка профиля; в раскрытом сайдбаре и мобильном меню рядом находится иконка выхода без фона. Профиль открывается в попапе, настройки оформления — кнопкой в топбаре рядом с переключением темы. Android, WA-аккаунты и APK убраны из меню; прямые маршруты сохранены.
- Фильтры редактируются только в одном попапе: плоский список условий с колонкой, оператором и значением. Условия объединяются через И; можно задать несколько сравнений для одной колонки. Отмена сохраняет применённые фильтры, кнопка применения отправляет весь набор сразу. Несколько статусов/тегов — «любое из выбранных». Никаких вложенных групп или конструктора логики.
- Название раздела находится в верхней панели `Workspace / Раздел`. Только в кампаниях над таблицей показаны три карточки статистики с иконками; создание сущности находится сразу после переключателя вида. На телефоне создание и обновление показывают только иконки с доступными подписями. Таблица занимает всю оставшуюся высоту через CSS flex; прокручиваются только строки внутри неё. JavaScript не измеряет высоту, не меняет scrollTop и не перехватывает wheel/touch. Лоадер с блюром появляется при первом открытии и пользовательских запросах — обновлении, фильтрах, сортировке и пагинации. Фоновое обновление раз в минуту и инвалидация данных проходят без оверлея.
- Таблицы автоматически выбирают компактный вид на телефоне и полный на компьютере. Есть два режима: адаптивные колонки с полными данными по `⋯` или горизонтальная прокрутка внутри таблицы. Кнопка рядом с «Колонки» мгновенно меняет режим. В «Колонки» можно выбрать видимые и приоритетные поля. Настройки сохраняются отдельно для каждой таблицы.
- Правый клик / долгое касание открывают контекстное меню. Те же действия есть в видимом `⋯`; массовые действия появляются после выделения чекбоксами. Цели касания обычно ≥44 px; у пагинации кнопки и селектор по запросу сохраняют 32 px, сам подвал — прежнюю высоту. Формы и попапы прокручиваются независимо, на телефонах диалоги открываются снизу, учитываются safe areas и reduced motion.
- Материалы Silver/Graphite из референса Native Gray: серебристые и графитовые поверхности, тонкие двойные грани, небольшие градиенты контролов. По умолчанию тёмная тема с лаймовым акцентом. Доступны только тёмная и светлая темы. Для каждой — четыре выбранных акцента в прямоугольных превью; старые настройки автоматически переводятся в новую палитру. Палитра и расчёт читаемого цвета текста — `src/lib/appearance.ts`, начальные CSS-токены — `src/app/globals.css`. Сохранены язык Русский/English и режим таблиц. Тёмная палитра синхронизирована с обновлённым графитом референса (`#26272a` / `#2f3033`), рельеф — 64%. Цвета статусов фиксированы. Все тексты интерфейса собраны в `src/lib/messages.ts`, контекст перевода — `src/lib/i18n.tsx`. Выбор сохраняется в браузере.

## Совместимость с существующим API

Используется существующий `/api/v1` без новых маршрутов FastAPI. Авторизация — `POST /auth/access-token` с OAuth form-urlencoded, Bearer JWT и периодическая проверка `/auth/test-token`. Сессия хранится под отдельным ключом `campaigner.workspace.session`.

Списки используют `{data,total}`, `skip`, `limit`, bracket-параметры `filters[0][field/operator/value]` и `orders[0][field/dir]`. Сериализатор находится в `src/lib/filters.ts`. Например:

```text
filters[0][field]=name&filters[0][operator]=contains&filters[0][value]=sale
orders[0][field]=id&orders[0][dir]=desc
```

Доступны существующие текстовые сравнения (`eq`, `neq`, `contains`, `doesnotcontain`, `startswith`, `endswith`, проверки пустоты/NULL), числовые и временные (`eq`, `neq`, `gt`, `gte`, `lt`, `lte`, NULL), логические (`istrue`, `isfalse`) и выбор значений (`in`, `overlaps`). Для `campaigns.status/tags` массив разворачивается в повторные скалярные `eq`, которые бэкенд сам объединяет. Сравнения предлагаются по типу колонки, без заведомо невалидных операторов для UUID и вычисляемых полей.

Подробная сверка старого UI: [docs/html-audit.md](docs/html-audit.md).

## Проверки

Unit-тесты проверяют полноту переводов, сохранение плейсхолдеров и точную сериализацию операторов, кодирование символов, NULL, чисел, массивов и сортировки. Browser-тесты проверяют реальные действия и API-контракты на desktop, iPhone 13 и экране 320 px. Нужен установленный Google Chrome (либо настройте browser/channel в `playwright.config.ts`).

```bash
npm run build
npm run test:e2e
```

По умолчанию тесты сами запускают и останавливают production-сервер. Для dev-сборки: `E2E_DEV=1 npm run test:e2e`.

Для проверки production сначала `npm run build`, затем `npm start` и в другом терминале:

```bash
E2E_BASE_URL=http://localhost:3000 npm run test:e2e
```

Для проверки загрузки и авторизации по локальной сети на запущенном dev-сервере: `E2E_BASE_URL=http://<локальный IPv4 компьютера>:3000 npm run test:e2e -- auth.spec.ts --project=touch`.

HTTP-проверка `npm run test:proxy` запускает настоящий production Next.js с временным тестовым upstream и проверяет точные пути, заголовки, cookies, multipart, JSON, redirects и бинарный отчёт.

Браузерные тесты перехватывают API-запросы и не отправляют настоящие сообщения. Полный live smoke с реальной БД и устройствами требует работающего API и учётной записи.

Формы создания и редактирования сохраняют порядок полей и разделителей `sepN` исходного `html`, булевы переключатели используют Radix Switch. Поля и селекты имеют высоту 36 px, textarea начинается с трёх строк. DateTimePicker использует стилизованный календарь и сохраняет исходный UTC-контракт. ID выводятся без разделителей разрядов. Данные таблиц прижимаются влево, перед меню действий добавлена пустая колонка для свободного места.

Компоненты shadcn хранятся исходниками в `src/components/ui`; `components.json` настроен для расширения. Подход соответствует [shadcn Data Table](https://ui.shadcn.com/docs/components/radix/data-table) и [Next.js SPA guide](https://nextjs.org/docs/app/guides/single-page-applications).

Снимки интерфейса на тестовых данных: [десктоп](docs/previews/desktop-dark.png), [светлая тема](docs/previews/desktop-light.png), [телефон 320 px](docs/previews/mobile-dark.png), [настройки светлой темы](docs/previews/appearance-light.png), [настройки на английском](docs/previews/appearance-english.png), [тёмная форма](docs/previews/form-dark.png), [светлая форма](docs/previews/form-light.png), [календарь](docs/previews/datetime-picker.png), [профиль](docs/previews/profile.png).
